# 위치 이력 보관 및 노출 정책

기준일: 2026-09-01

## 목적

최신 제품 목표는 환자 GPS 좌표를 1분 주기로 공유하는 것이다. 현재 코드는 매니저 단말 위치를 더 짧은 주기로 공유하므로 목표와 구현이 다르다. 이 문서는 제품 목표, production 활성화 조건과 이미 구현된 기술 안전망을 구분한다.

## 제품 정책 상태

- 환자 GPS 좌표를 1분 주기로 공유하는 기능을 제품 목표로 한다.
- 4자리 상봉번호는 사용하지 않는다. Figma의 상봉번호 화면은 디자인 이력으로만 유지한다.
- 제품 목표 확정과 production 활성화는 별개다. 환자의 명시적 동의·즉시 철회, 공유 대상별 인가, 1분 서버 제한과 종료·취소 시 즉시 삭제 시도·24시간 이내 재시도 완료를 종단 검증하기 전에는 위치 수집·공유를 `OFF`로 유지한다.

## 현재 코드 기준

- Android는 배정 매니저 단말 위치를 Spring Core API를 통해 기록하고 PostgreSQL을 업무 원본으로 사용한다.
- `ManagerLiveLocationTracker`는 10초 또는 15m 이동을 전송 기준으로 사용한다. 이는 환자 GPS 1분 공유 목표와 주체·주기가 모두 다르다.
- `companion_session_locations`는 세션별 최근 10건과 최신 위치 snapshot을 유지한다.
- Supabase Realtime private Broadcast는 PostgreSQL 커밋 알림이며 재연결 시 Core API snapshot을 다시 읽는다.
- Core 업무 위치의 Firestore client 쓰기는 차단됐다. Firestore의 `sharedLocationHistory`와 최신 좌표 필드는 전환 데이터 파기 경계에서만 남아 있다.
- 위치·채팅 전환과 매니저 위치 실기기 검증은 완료했지만, 환자 GPS 공유 구현이나 production 활성화 증거는 아니다.

## PostgreSQL 전환 계약

- V8 migration은 `companion_session_locations`에 배정 매니저 좌표와 `manager_user_id`를 행 단위로 저장하고 세션별 최근 10건만 유지한다.
- Core runtime도 table에 직접 INSERT하지 않고 `record_companion_location` 함수로만 기록한다. 함수는 배정 매니저, 진행 상태, 수집 시각과 중복 식별자를 검증한다. 환자 위치는 이 계약을 그대로 재사용하지 않는다.
- 세션 완료·취소 시 각 위치 행의 `expires_at`을 종료 시각 24시간 뒤로 예약한다.
- V8 저장·만료 계약과 #222 개발 파기 APPLY는 검증됐다. production 쓰기 권한과 정기 apply는 정책·약관 승인 전 비활성 상태다.
- 현재 정리 작업은 하루 한 번 실행되므로 `종료+24시간` 만료 뒤 실제 삭제가 24시간을 넘을 수 있다. 이는 즉시 삭제 시도·24시간 최종 상한이라는 제품 정책을 충족하지 않으며 production 활성화 전에 교체해야 한다.

## 보관 정책

| 기존 구현 데이터 | 기술 보관 기준 | 개발·전환 목적 |
| --- | --- | --- |
| 최신 좌표 | `companion_session_locations`의 최신 유효 행 | 기존 위치 화면과 개발 검증의 snapshot 복구 |
| 최근 위치 이력 | `companion_session_locations`에서 세션당 최근 10행만 유지 | 기존 위치 화면과 파기 경로 검증 |
| 위치 요약 텍스트 | `companion_sessions.location_summary`에 유지 | 정밀 좌표 없이 현장 상황을 설명 |
| 완료·취소 후 정밀 좌표 | 즉시 삭제 시도, 최대 24시간 이내 삭제 | 개인정보 최소 보관, 실패·지연 처리 재시도 |
| 수집·이용·제공사실 확인자료 | 6개월 | 좌표 없이 주체·목적·시각·제공 대상만 감사 기록 |
| 운영 리포트 | 좌표 원본 대신 요약 문구 중심으로 유지 | CS, 품질 점검, 분쟁 대응 |

이 표의 즉시 삭제·24시간 최종 상한은 향후 환자 위치에 적용할 정책이며 GPS 수집을 production에 승인한 표가 아니다. 현재 개발·전환 데이터는 완료 또는 취소 시 `expires_at`을 종료 시각의 24시간 뒤로 설정하고 일 1회 정리 job이 삭제하므로 상한을 보장하지 못한다. 정리 지연 중에도 완료된 세션의 원본 좌표를 일반 화면에 노출하지 않으며 장기 분석 데이터로 사용하지 않는다.

## 화면 노출 기준

아래 화면 기준은 개발·검증 환경에서 기존 매니저 위치 기능을 확인할 때만 적용한다. production에서는 환자 위치 동의·철회·인가·파기 종단 검증과 전역 활성화 승인이 끝날 때까지 위치 화면과 권한 요청을 노출하지 않는다.

### 보호자/환자

- 진행 중 세션에서는 최신 위치, 최근 위치 이력, 마지막 갱신 시각을 표시한다.
- 완료 또는 취소된 세션에서는 위치 원본 이력보다 최종 리포트와 위치 요약을 우선 표시한다.
- 위치 정보가 없거나 공유가 중지된 경우에는 대기/공유 중지 상태를 명확히 표시한다.

### 매니저

- 본인이 배정된 진행 중 세션에서만 위치 공유 시작/중지와 위치 갱신을 수행한다.
- 최근 위치 이력은 현장 진행 확인과 보호자 공유 상태 점검용으로만 표시한다.
- 완료 또는 취소 후에는 위치 공유를 중지하고 추가 좌표 갱신을 하지 않는다.

### 관리자

- 관리자 화면은 운영 대응을 위해 최신 위치 상태, 위치 요약, 최근 이력을 제한적으로 확인할 수 있다.
- 장기 보관 목적의 전체 이동 경로 조회 화면은 MVP 범위에 포함하지 않는다.
- 분쟁 대응이 필요한 경우에도 원본 좌표 장기 보관보다는 세션 요약, 최종 리포트, 감사 로그를 우선 사용한다.

## 개인정보 및 운영 기준

- 위치 좌표는 목적 외 재사용을 금지한다.
- 보호자/환자에게 보이는 문구는 위치 공유 상태와 마지막 갱신 시각을 오해 없이 표현해야 한다.
- 위치 공유 중에는 배터리, 네트워크, 권한 상태에 따라 갱신이 지연될 수 있음을 UI에서 안내한다.
- 민감 위치 원본을 별도 리포트나 분석 데이터로 장기 저장하지 않는다.
- 개인정보 삭제 요청이 들어오면 해당 사용자와 연결된 진행 종료 세션의 위치 원본 삭제 범위를 우선 검토한다.
- 분쟁 또는 법적 의무에 따른 예외 보관은 대상 세션, 근거, 승인자와 종료일을 기록한 legal hold로만 허용한다.

## production 활성화 전 필수 구현

- 앱 UI와 Core API가 함께 확인하는 production 전역 위치 모드 `off`를 기본값으로 둔다.
- 환자 본인만 좌표를 제출할 수 있는 별도 API·DB 계약을 만들고 기존 `manager_user_id` 위치 행과 구분한다.
- Android 전송 간격뿐 아니라 Core API에서도 사용자·세션별 1분 제한과 중복 요청 멱등성을 강제한다.
- 환자의 명시적 동의와 즉시 철회, 철회 뒤 신규 전송·열람 차단, 공유 대상별 최소권한을 역할별로 검증한다.
- 동행 종료·취소 transaction에서 원본 좌표를 일반 조회에서 즉시 제외하고 삭제를 시도하며, 실패한 건만 24시간 이내 재시도한다.
- 개인정보 삭제 요청과 법정 보존 분리를 처리하는 계정 삭제 흐름.
- 기존 개발·전환 위치 데이터에 대한 24시간 파기 안전망 유지와 production 격리 검증.

## 기술 안전 기본값

- 정밀 좌표 삭제: 세션 완료·취소 시 즉시 시도, 실패·지연 건도 최대 24시간 이내 완료
- 위치정보 수집·이용·제공사실 확인자료: 6개월
- 장기 운영 리포트: 정밀 좌표와 전체 경로를 제외한 병원·행정구 또는 상태 요약만 허용
- 기술 기본 legal hold: 최대 180일, 더 긴 보관은 별도 법적 근거 필요

이 값은 위치 기능의 운영 승인이 아니라 이미 생성된 개발·전환 데이터와 향후 게이트 통과 뒤 생성될 위치 원본의 최대 보관 안전망이다.

상세 공통 기준은 [데이터 보관 및 파기 정책](data-retention-policy.md)을 따른다.

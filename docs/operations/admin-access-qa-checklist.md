# 관리자 웹/앱 권한 QA 체크리스트

관리자 웹 기준 갱신: 2026-09-21. 앱 숨김 진입 시나리오는 기존 레거시 경로이며 이번 문서 갱신에서 실기기로 재검증하지 않았다.

이 문서는 `관리자 앱 진입`, `관리자 웹 로그인`, `매니저 서류 검토`, `권한 실패 시나리오`를 반복 검증하기 위한 체크리스트다. 아래 기대 결과는 시험 기준이며 실행 완료 기록이 아니다. 최신 환경 준비 상태는 [관리자 웹 환경 기준](admin-web-environments.md)을 먼저 확인한다.

## 목적

- 일반 사용자 경로에서 관리자 기능이 노출되지 않는지 확인
- 관리자 계정만 앱/웹에서 관리자 기능에 접근하는지 확인
- 매니저가 업로드한 증빙의 검증된 세대로 서버가 보호 파생본을 생성하고, 브라우저에 원본을 노출하지 않는지 확인
- Firestore / Storage 권한 축소 이후 주요 화면이 깨지지 않는지 확인

## 사전 준비

### 계정

- 대상 Firebase 프로젝트에 관리자·매니저·환자·보호자 검증 계정을 각각 준비한다. 이메일과 비밀번호는 비공개로 전달하며 이 문서의 고정 예시를 공용 자격 증명으로 사용하지 않는다.
- 웹 관리자는 PostgreSQL `app_users`의 `ADMIN` 진입 자격과 활성 세부 역할이 필요하다. `SUPER_ADMIN`, `OPERATIONS`, `DEVELOPER`, 세부 역할 없는 관리자도 구분해 준비한다.
- Firebase Auth 계정 생성과 비밀번호 재설정 메일 발송은 관리자 역할 부여나 MFA 완료가 아니다. 개발 계정이 운영 Firebase 프로젝트에 자동 등록되지는 않는다.
- 운영 DB가 중지되거나 접속 설정이 준비되지 않았다면 권한·업무 시험은 `미실행`으로 기록한다. QA를 이유로 승인 없이 DB를 재개하거나 운영 fixture를 만들지 않는다.

### 로컬 점검

```powershell
cd D:\BoDeul
.\gradlew.bat assembleDebug
cd D:\BoDeul\tools\firebase
npm run check:state
npm run check:readiness
npm run check:manager-storage -- --strict
```

### 웹 실행

```powershell
cd D:\bodeul-admin-web
npm ci
npm run dev
```

- 별도 웹 저장소의 기본 Next.js 개발 주소: `http://localhost:3000`
- 개발 Firebase·DB 설정은 비공개 `.env.local`에 주입한다. 메인 저장소의 과거 `admin-web/` 산출물은 실행 기준이 아니다.

## 1. 앱 관리자 진입

### 1-1. 공개 경로 노출 확인

1. 앱을 실행한다.
2. 역할 선택 화면을 확인한다.

기대 결과:

- 공개 카드에는 `환자`, `보호자`, `매니저`만 보인다.
- `관리자` 카드가 직접 노출되지 않는다.

### 1-2. 숨김 관리자 진입 확인

1. 역할 선택 화면 상단 로고를 `1.5초 안에 5회 탭`한다.
2. 관리자 로그인 화면으로 이동하는지 확인한다.

기대 결과:

- 관리자 로그인 화면으로 진입한다.
- 관리자 로그인 화면에서는 이메일 로그인만 가능하다.
- 회원가입, 소셜 로그인 진입은 보이지 않는다.

### 1-3. 일반 경로 오입력 차단 확인

1. 공개 `환자`, `보호자`, `매니저` 경로 중 하나로 로그인 화면에 들어간다.
2. 해당 개발 환경의 관리자 검증 계정을 입력한다.

기대 결과:

- `선택한 사용자 유형과 계정 유형이 일치하지 않습니다.` 류의 실패 메시지가 나온다.
- 관리자 화면으로 진입하지 않는다.

### 1-4. 관리자 로그인 성공 확인

1. 숨김 관리자 진입 경로로 로그인 화면에 들어간다.
2. 해당 개발 환경의 관리자 검증 계정으로 로그인한다.

기대 결과:

- 관리자 대시보드로 진입한다.
- 일반 사용자 홈이나 예약 화면으로 가지 않는다.

## 2. 관리자 웹 로그인

### 2-0. 접속 환경 표시

1. 로컬 개발 서버·Vercel Preview·Production의 로그인 화면에서 상단 표시를 확인한다.
2. 검증용 화면 또는 준비된 개발 계정으로 세션 확인·2차 인증·관리 셸에서도 표시가 유지되는지 확인한다.
3. 좁은 모바일 화면과 스크롤 상태에서 내용이 겹치거나 가로로 넘치지 않는지 확인한다.

기대 결과:

- Production은 `운영 환경`, Preview·로컬 개발 서버는 `개발 환경`이며 상세 문구로 Preview와 Local을 구분한다.
- 배포 정보가 없는 최적화 빌드는 `환경 확인 필요`로 표시한다. `NODE_ENV=production`만으로 운영으로 판단하지 않는다.
- 실제 운영 로그인 없이 fixture로 셸을 확인했다면 그 한계를 기록한다. 배너 확인을 DB 연결·관리자 권한 통과로 대신하지 않는다.

### 2-1. 관리자 로그인 성공

1. 준비된 개발 사이트 또는 `http://localhost:3000`에 접속하고 환경 표시를 확인한다.
2. 해당 Firebase 프로젝트의 `SUPER_ADMIN` 또는 `OPERATIONS` 검증 계정으로 로그인하고, 2차 인증이 요청되면 완료한다.

기대 결과:

- 관리자 웹 메인 화면이 열린다.
- 역할에 허용된 매니저 심사 목록, 상태 배지, 환경 표시와 로그아웃 버튼이 보인다.
- `DEVELOPER`는 운영·심사 메뉴와 API가 제한되며, 세부 역할 없는 `ADMIN`은 서버에서 거부된다.

### 2-2. 비관리자 로그인 차단

1. 로그아웃한다.
2. 같은 환경의 매니저 또는 환자 검증 계정으로 로그인한다.

기대 결과:

- 관리자 화면이 열리지 않는다.
- 비관리자 계정은 즉시 차단되거나 로그인 화면으로 되돌아간다.

### 2-3. 로그아웃 동작 확인

1. 관리자 웹 로그인 상태에서 로그아웃을 누른다.
2. 새로고침한다.

기대 결과:

- Firebase 세션이 종료되어 다시 로그인 화면이 보인다.
- `localStorage` 플래그만으로 관리자 화면이 다시 열리지 않는다.

### 2-4. 목록 기본 마스킹 확인

1. 관리자 웹 로그인 상태에서 매니저 승인 목록을 본다.
2. 이메일과 전화번호 열을 확인한다.

기대 결과:

- 목록에서는 이메일과 전화번호가 마스킹되어 보인다.
- 상세 보기 모달을 열기 전까지는 전체 값이 그대로 노출되지 않는다.

### 2-5. 유휴 세션 자동 종료 확인

1. 관리자 웹 로그인 상태로 둔다.
2. 입력, 클릭, 스크롤 없이 `15분` 이상 둔다.

기대 결과:

- 자동 로그아웃된다.
- 로그인 화면으로 돌아간다.
- `보안을 위해 15분 동안 활동이 없어 자동 로그아웃했습니다.` 안내가 보인다.

## 3. 매니저 서류 검토

### 3-1. 매니저 서류 미리보기 확인

1. 관리자 웹에서 검증용 매니저 항목을 연다.
2. 확인 사유를 10자 이상 입력하고 `license` 또는 `nursingLicense` 자격 증빙 1종의 보호 미리보기를 확인한다.

기대 결과:

- 서버가 형식과 세대를 검증한 JPEG·PNG·WebP 원본에서 워터마크 파생본을 만들며, 브라우저에는 원본 경로·다운로드 URL·신분증·범죄경력 원본을 노출하지 않는다.
- PDF와 지원하지 않는 형식은 성공 미리보기로 취급하지 않고 거부한다.
- 감사 실패 시 파생본과 증거 token을 반환하지 않는다.
- 메타데이터 경로가 끊긴 경우 다른 파일로 자동 대체하지 않고 오류 상태를 보여준다.

### 3-2. 심사 승인/반려 저장 확인

1. `PENDING_REVIEW`인 검증용 매니저의 현재 자격 증빙을 보호 미리보기로 확인한 뒤 승인한다.
2. 별도의 `PENDING_REVIEW` 검증 항목에서 반려 메모를 넣고 반려한다. 승인한 항목을 같은 revision으로 다시 처리하는 것은 정상 경로로 보지 않는다.

기대 결과:

- 심사 상태가 Firestore에 반영된다.
- `managerDocumentStatus`, `managerDocumentReviewNote`, `managerDocumentReviewedAt`, `managerDocumentReviewedByName`, `managerDocumentHistory`가 함께 갱신된다.
- 승인 시 만료·변조·다른 문서 세대·revision의 증거 token은 거부하며 심사 상태를 변경하지 않는다. 성공·거부·실패의 감사 경계는 [웹 서버 계약](https://github.com/bodeul110/bodeul-admin-web/blob/master/docs/nextjs-admin-server.md)을 따른다.

## 4. 앱-웹 연동 확인

### 4-1. 매니저 앱 업로드 후 웹 반영 확인

1. 매니저 앱 내 페이지에서 원본 파일을 업로드한다.
2. 관리자 웹에서 같은 매니저 항목을 다시 연다.

기대 결과:

- `managerDocumentFiles` 메타데이터와 Storage 경로가 함께 저장된다.
- 관리자 웹이 새 문서 세대·revision에 대한 보호 파생본과 새 증거 token을 사용한다.

### 4-2. Storage 점검 확인

```powershell
cd D:\BoDeul\tools\firebase
npm run check:manager-storage -- --strict
```

기대 결과:

- `missingObjectCount = 0`
- `pathMismatchCount = 0`
- `orphanObjectCount`는 0이거나, 정리 전이면 리포트로만 남는다.

## 5. 권한 실패 시나리오

### 5-1. Firestore 직접 읽기 차단

검증 기준:

- 일반 사용자(`patient`, `guardian`, `manager`)는 다른 사용자의 `users/{uid}` 문서를 직접 읽지 못해야 한다.
- 본인 `users/{uid}`는 읽을 수 있어야 한다.
- 관리자 웹은 브라우저의 `ADMIN` 주장만으로 타 사용자 문서를 직접 읽는 경로를 사용하지 않고 Next.js 서버 인가를 거친다. 실제 Rules와 레거시 관리자 앱의 허용 범위는 대상 환경 배포본과 함께 별도로 확인한다.

이미 반영된 자동 검증:

- [../security/firestore-hardening.md](../security/firestore-hardening.md)

### 5-2. Storage 정리 전 안전장치 확인

```powershell
cd D:\BoDeul\tools\firebase
npm run cleanup:manager-storage:dry-run
```

기대 결과:

- `--apply` 없이 실제 삭제가 일어나지 않는다.
- 누락 객체나 경로 불일치가 있으면 삭제 차단 사유가 출력된다.

## 6. 통과 기준

아래를 모두 만족하면 해당 환경의 관리자 권한 QA를 통과로 본다. 미실행 항목이 있으면 부분 검증으로 남기며, 개발에서 통과한 결과를 운영 통과로 복사하지 않는다.

- 앱 역할 선택 화면에 관리자 공개 카드가 없다.
- 숨김 진입으로만 관리자 앱 로그인 가능
- 일반 경로에서 관리자 계정 오입력 시 차단
- 관리자 앱 로그인 성공
- 웹 환경 표시가 접속 대상과 일치하며 모바일·스크롤·인증 단계에서도 유지됨
- 관리자 웹에서 관리자 계정만 로그인 성공
- 관리자 웹 로그아웃 후 새로고침 시 세션 유지되지 않음
- 관리자 웹 목록 기본 마스킹 적용 확인
- 관리자 웹 유휴 세션 자동 종료 확인
- 매니저 증빙의 워터마크 파생본과 증거 token 검증, 미지원 형식·감사 실패 거부 확인
- 심사 승인/반려 저장 정상
- `check:manager-storage -- --strict` 통과
- 타 사용자 `users/{uid}` 직접 읽기 차단 확인

## 7. 실패 시 기록 항목

실패하면 아래를 같이 남긴다.

- 실패 화면 또는 URL, 화면의 환경 표시와 deployment/commit
- 사용 계정의 역할과 비식별 식별자. 비밀번호·token·개인 이메일은 공개 문서에 남기지 않음
- 실패 단계 번호
- 기대 결과와 실제 결과
- 관련 리포트 경로
  - `tools/firebase/reports/manager-document-storage-check-*.json`
  - `tools/firebase/reports/firestore-operations-report-*.html`
  - `tools/firebase/reports/local-preflight-summary-*.md`

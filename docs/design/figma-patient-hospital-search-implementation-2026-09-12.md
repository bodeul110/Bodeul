# 환자 병원 검색 화면 피그마 반영 결정 기록

## 대상

- Figma `보들 MVP`의 병원 검색 화면 (`8:398`)
- Android `BookingHospitalSelectorActivity`

## 결정

- 기존 예약 작성 흐름과 `BookingHospitalSelectorActivity`의 검색·병원 선택·진료과 선택·직접 입력 동작은 유지한다.
- 상단 앱 바, 검색창, 지역 카드, 병원 목록 카드의 배치·간격·색상·아이콘을 Figma 기준으로 재구성한다.
- 지역 카드는 장식용으로 두지 않고 서울 전체, 종로구, 강남구 키워드를 실제 병원 검색에 전달한다.
- 병원 목록에는 현재 앱이 보유한 병원명, 진료과, 좌표만 표시한다.
- 작은 화면·키보드 표시·큰 글꼴에서 결과 목록이 접히지 않도록 지역 바로가기는 공간이 부족할 때 숨기고 검색창·결과·직접 입력은 유지한다.
- 이 화면은 예약 폼에서 결과를 반환받는 하위 선택 화면이므로 Figma의 하단 전역 탭은 넣지 않는다.
- 상태 표시줄과 탐색 영역의 시스템 인셋을 적용해 실제 기기에서도 상단 앱 바와 콘텐츠가 겹치지 않게 한다.
- 디버그 자동 진입 화면에 병원 검색 경로를 추가해 상위 예약 API 상태와 무관하게 UI 회귀 검증이 가능하도록 한다.

## 대안과 제외 이유

- Figma 샘플의 병원 사진·주소·병원 유형을 고정값으로 표시하는 방법은 실제 API 응답과 다른 정보를 만들기 때문에 제외했다.
- 하단 전역 탭을 그대로 추가하는 방법은 작성 중인 예약 값을 잃고 다른 화면으로 이동할 수 있어 제외했다.
- 검색 결과가 없을 때 직접 입력 기능을 제거하는 방법은 기존 예약 진행 경로를 막기 때문에 제외했다.

## 작은 화면 보완 판단

- 작업 목적: 분할 화면이나 키보드 표시로 가용 높이가 줄어도 병원 검색 결과와 직접 입력을 선택할 수 있게 한다.
- 선택한 방식: 결과 카드 한 장을 표시할 수 있는 높이가 부족하면 지역 바로가기 제목과 카드만 접고, 높이가 회복되면 다시 표시한다. 큰 글꼴일수록 필요한 높이를 높여 판단한다.
- 대안: 모든 요소를 고정 배치하거나 결과 목록을 전체 스크롤 영역 안에 넣는 방식을 검토했다.
- 선택 이유: 현재 MVP에서는 기존 `ListView`의 검색·선택 동작을 유지하면서 상단 장식성 바로가기만 접는 편이 데이터·스크롤 계약 변경이 가장 작다.
- 리스크: 중간 높이에서도 지역 바로가기가 숨겨질 수 있다. 실제 작은 화면·큰 글꼴·키보드 검색을 연결된 기기에서 다시 확인한다.

## 위험과 후속 작업

- 병원 사진, 주소, 병원 유형이 API 모델에 추가되면 병원 카드에 해당 정보를 연결해야 한다.
- 지역 목록이 서버나 기획에서 확정되면 현재 3개 바로가기를 동적 데이터로 교체한다.
- 실제 기기에서 작은 화면, 큰 글꼴, 검색 결과가 많은 경우의 스크롤과 터치 동작을 확인한다.

## 검증

- `gradlew assembleDebug --console=plain --max-workers=1`: 성공
- `git diff --check`: 성공
- `lintDebug`: 이번 변경에서 발생한 오류는 0건이다. 기존 `GuardianSharingConsentActivity`와 `activity_manager_home.xml`의 오류 7건 때문에 전체 작업은 실패한다.
- `testDebugUnitTest`: 테스트 코드 실행 전 Gradle 테스트 작업자가 `GradleWorkerMain`을 찾지 못하는 로컬 실행 환경 문제로 실패한다. 앱과 테스트 소스 컴파일 단계는 통과했다.
- 실제 기기 `SM-S901N`에 디버그 APK 설치와 병원 검색 화면 자동 진입이 성공했다.
- 첫 진입에서 Figma 위치 아이콘의 잘못 변환된 vector path로 인한 크래시를 발견해 수정했고, 재설치 후 크래시 없이 화면이 표시되는 것을 확인했다.
- 상태 표시줄·탐색 영역 인셋, 앱 바, 검색창, 지역 카드 3개, 병원 결과 카드가 411dp 폭 기기에서 겹침 없이 표시된다.
- 종로구 지역 카드를 누르면 검색어가 `서울 종로구`로 바뀌고 결과가 0건으로 갱신되며, 서울 전체 카드를 누르면 `서울` 검색 결과 1건이 표시된다.
- 진료과가 1개인 병원 선택과 병원·진료과 직접 입력 모두 결과 반환 후 화면이 정상 종료된다.
- 상위 예약 화면은 검증 시점에 Core API 연결 실패 상태여서 디버그 자동 진입 경로로 선택 화면을 독립 검증했다.
- 2026-09-15 작은 화면 보완 후 `assembleDebug` 성공, 새 레이아웃 정책 JUnit 3건 직접 실행 성공, `git diff --check` 성공을 확인했다.
- 같은 보완의 `lintDebug`는 기존 오류 7건으로 실패했고 이번 변경 파일에서 신규 오류는 없었다. Gradle `testDebugUnitTest`는 테스트 소스 컴파일 후 Windows 테스트 실행기의 `GradleWorkerMain` 로딩 오류로 본문 실행 전에 실패했다.
- 이번 작은 화면 보완은 연결된 실기기가 없어 분할 화면·키보드·큰 글꼴에서 실제 선택 동작을 재확인하지 못했다.

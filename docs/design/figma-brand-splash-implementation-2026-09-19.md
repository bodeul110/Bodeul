# Figma 브랜드 시작 화면 구현 기록

## 기준

- Figma MVP 파일의 `첫 화면` node `8:179`
- Android Views, Java와 XML 기반의 현재 인증 화면 구조
- 기존 `EntryFlowCoordinator`의 권한 안내·역할 선택·로그인 후 화면 분기

## 구현한 내용

- `SplashActivity`를 앱의 launcher activity로 지정하고 역할 선택 화면은 내부 화면으로 전환했다.
- Figma의 배경색, 우상단 파란 빛, 좌하단 주황 빛, 중앙 로고·태그라인과 하단 진행 표시를 전용 XML로 구성했다.
- Figma에서 조회한 로고 자산과 기존 `bodeul_logo_figma.png`의 크기와 SHA-256 해시가 같아 기존 원본을 재사용했다.
- 인증 상태 조회가 빠르게 끝나도 화면을 최소 900ms 노출하고, 3초 이상 지연되면 역할 선택으로 이동해 기존 진입 흐름에서 다시 확인하도록 했다.
- 앱이 이미 로그인된 상태라면 역할 선택을 거치지 않고 기존 역할별 화면으로 이동한다.

## 설계 판단

- 작업 목적: 앱 실행 직후 역할 선택 화면이 바로 나타나는 흐름을 Figma MVP의 브랜드 시작 화면과 맞춘다.
- 선택한 방식: 전용 `SplashActivity`가 최소 900ms 동안 브랜드 화면을 표시하면서 기존 `EntryFlowCoordinator`로 인증·권한 상태를 확인하고, 3초 안에 확인되지 않으면 권한 안내를 포함한 기존 로그아웃 진입 경로로 이동한다.
- 대안: 역할 선택 화면 안에 시작 레이어를 겹치거나 고정 지연만 둔 뒤 항상 역할 선택으로 보내는 방식을 검토했다.
- 선택 이유: 현재 인증 분기를 한곳에서 재사용하면 로그인된 사용자의 불필요한 역할 선택 노출과 최초 권한 안내 누락을 막을 수 있고, 조회 지연의 최대 시간을 두면 시작 화면에 갇히지 않는다.
- 리스크: 3초 타임아웃 뒤에는 역할 선택 화면에서 인증 조회가 한 번 더 일어날 수 있다. 인증 저장소 응답 시간이 장기적으로 느려지면 시작 상태 모델과 오프라인 분기를 별도로 설계한다.

## 화면 대응

| Figma 속성 | Android 적용 |
| --- | --- |
| 390×998, 배경 `#F7F9FC` | 전체 화면 `FrameLayout`, `figma_mvp_background` |
| 336×238 로고 이미지 | 기존 `bodeul_logo_figma`를 같은 비율로 표시 |
| Pretendard Medium 20px 태그라인 | `pretendard_medium`, 20sp, 28dp 계열 행간 |
| 192×6 진행 표시, 1/3 파란 그라데이션 | 192dp 트랙과 64dp 그라데이션 채움 |
| 하단 10px 영문 문구 | `pretendard_regular`, 10sp, 글자 간격 0.1 |

## 검증 기준

- 시작 화면 최소 노출 시간 계산 단위 테스트
- 전체 debug 단위 테스트와 `assembleDebug`
- 실기기에서 콜드 스타트, 최초 권한 안내, 로그아웃 역할 선택과 로그인 상태 자동 이동 확인
- 작은 화면과 시스템 상태·내비게이션 영역에서 로고와 진행 표시가 잘리지 않는지 확인

## 남은 범위

- 실기기 캡처를 Figma node와 나란히 비교해 시스템 바와 세로 위치를 최종 보정한다.
- 실제 인증 저장소가 3초 이상 지연되는 환경에서는 역할 선택 화면의 재조회 상태를 별도로 관찰한다.

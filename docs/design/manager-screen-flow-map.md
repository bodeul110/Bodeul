# 매니저 화면 흐름 지도

기준일: 2026-08-25

## 작업 목적

실기기 캡처에서 확인한 현재 Android 화면을 Figma의 목표 화면군과 연결하고, 한 화면에 임시로 모인 기능을 어떤 순서로 분리할지 정한다.

## 현재 흐름과 목표 매핑

| --- | --- | --- | --- | --- |
| 1 | 매니저 로그인 | `activity_login.xml` | 로그인 `845:84` | 유지하고 시각 기준만 맞춘다. |
| 2 | 사용자 유형 선택 | `activity_role_selection.xml` | 사용자 설정 `845:134` 계열 | 역할 선택과 다음 화면 연결을 유지한다. |

## 최상위 내비게이션

매니저의 최상위 목적지는 `홈`, `이력`, `가이드`, `내 정보`로 유지한다. 로그인, 권한, 자격 인증, 서류 제출, 채팅과 가이드 내부 작업 화면에서는 뒤로 가기를 사용한다.

매니저 하위 화면의 빈 상태나 로드 오류에서 `홈으로`를 선택하면 환자 홈인 `MainActivity`를 거치지 않고 `ManagerActivity`로 직접 복귀한다. 인증된 사용자가 매니저 역할이 아닐 때만 일반 홈과 역할 선택 경로를 제공한다.

## 매니저 홈 상태

### 활성 동행 없음

- 승인·서류 상태
- 예정 일정 또는 서비스 안내
- 서류, 일정, 이력, 문의 빠른 관리
- 요청 목록은 서버의 매니저 self-accept 계약이 생기기 전까지 실제 수락 기능으로 연결하지 않는다.

### 활성 동행 있음

- 현재 동행 세션을 첫 번째 카드로 강조
- 가이드 이어가기
- 환자·병원·예약 시간·보호자 연락처 요약
- 안심 채팅 진입
- 빠른 관리와 하단 내비게이션

## 동행 가이드 분리 원칙

Figma의 13개 화면을 13개 Activity로 만들지 않는다. `ManagerGuideActivity`와 서버의 현재 단계는 유지하고, `ManagerGuideStepRegistry`가 단계 코드를 화면 표현 유형으로 연결한다.

1. 매칭·상봉
2. 병원 이동
3. 접수·대기
4. 기초 측정 기록
5. 문진 준비
6. 진료 보조·기록
7. 진료 리포트 확인
8. 수납·결제 증빙
9. 약국 이동
10. 처방 관련 자료 등록
11. 복약 확인
12. 환자 최종 확인·동행 종료
13. 매니저 일지·후기 진입

현재 단계의 카드와 CTA만 우선 강조하고, 이전 단계는 요약하며 미래 단계는 숨기거나 잠금 처리한다. 결제 증빙, 처방 이미지와 매니저 일지는 서버 필드·필수 여부·보관 정책이 확정되기 전까지 완료 기능처럼 표시하지 않는다.

가이드 12와 13은 현재 서버에서 하나의 `completedAt`으로 처리된다. `CARE_ENDED`와 `COMPLETED` 계약이 분리되기 전에는 화면만 독립 완료 상태로 구현하지 않는다.

서버가 새 `stepCode`를 추가해도 Android가 순번만 보고 기존 단계의 의미를 추정하지 않는다. 코드가 있는 미지원 단계는 공통 현장 메모만 제공하고, 코드가 비어 있는 기존 7단계 데이터에만 순번 기반 호환 표시를 사용한다.

## 구현 순서

1. 역할에 맞는 홈 복귀 경로를 정리한다.
2. 매니저 홈의 활성 동행 없음·있음 상태를 실기기에서 각각 검증한다.
3. 현재 서버 단계 코드와 Figma 가이드 1~13의 대응표를 확정한다.
4. 가이드에서 현재 단계 외의 입력 영역을 접거나 숨기는 렌더링을 적용한다.
5. 채팅, 지도와 파일 선택은 가이드의 보조 화면으로 연결한다.
6. 프로필에서 서류 제출·검토 이력을 별도 책임으로 분리한다.
7. Figma 접근이 가능해지면 화면별 색상·서체·간격을 보정한다.

## 검증 기준

- 매니저 하위 화면의 빈 상태와 로드 오류에서 매니저 홈으로 직접 복귀한다.
- 역할이 매니저가 아닌 사용자는 매니저 홈으로 진입하지 않는다.
- 활성 동행이 없을 때 가이드 진입은 차단되고 안내가 표시된다.
- 활성 동행이 있을 때 홈에서 가이드와 채팅으로 진입할 수 있다.
- 미지원 `stepCode`는 순번이 1 또는 7이어도 지도나 최종 리포트 입력을 노출하지 않는다.
- Android Debug 빌드가 성공한다.

## 남은 범위

- Figma MCP 한도 때문에 2026-08-25의 최신 시각값은 다시 조회하지 못했다.
- 실기기 세션이 `GUIDE_NOT_READY` 상태여서 준비 중 화면까지 확인했으며, 13단계 실제 전환은 단계 snapshot이 있는 테스트 세션에서 후속 검증해야 한다.
- 환자·보호자 실기기 흐름은 이번 매니저 화면 정리 범위에 포함하지 않았다.
- 매니저 요청 수락은 현재 서버 권한 계약에 없으므로 별도 제품·백엔드 결정이 필요하다.

# Figma 환자·보호자 홈 화면 구현

기준일: 2026-09-12

## 기준

- Figma 파일: `보들 MVP` (`NX07k3Tu4cLc6YgAV82RXp`)
- 대상 노드: `환자 홈 화면` (`8:194`)
- Android 진입점: `MainActivity`

## 설계 판단

- 작업 목적: 환자·보호자 홈을 Figma의 상단 앱 바, 인사, 주요 상태 카드, 2×2 빠른 메뉴, 서비스 소개와 하단 내비게이션 위계에 맞춘다.
- 선택한 방식: 기존 `MainActivity`, `ClientHomeCoordinator`와 실제 예약·문의 상태 계약은 유지하고 전용 XML과 바인더의 표시 책임을 재구성한다.
- 대안: Figma의 환자 홈에 잘못 들어간 매니저용 서류·스케줄·과거 경력 카드를 그대로 복제하거나 홈 기능을 정적 샘플 데이터로 교체하는 방식을 검토했다.
- 선택 이유: 현재 MVP에서는 환자에게 실제로 제공되는 동행 신청, 건강정보, 일정·이력과 문의 기능을 노출하면서 Figma의 시각 위계를 재사용하는 편이 역할 혼동과 기능 회귀를 줄인다.
- 리스크: Figma의 위치와 주변 매니저 수는 환자 홈 API에 없고, AI 매칭 표현은 구현 완료 기능이 아니므로 화면에 가짜 숫자나 AI 제공 문구를 표시하지 않는다.

## 구현 범위

- 고정 상단 앱 바, 36sp 인사말, 48dp 모서리의 파란 상태 카드와 주황색 주요 동작을 적용한다.
- 2×2 카드에는 동행 신청, 건강정보, 일정·이력, 문의를 연결하고 실제 예약 건수와 읽지 않은 문의 수를 표시한다.
- 진행 중인 대표 예약이 있을 때만 기존 진행 로드맵을 표시한다.
- Figma에서 내려받아 이미 저장소에 반영된 로고와 서비스 소개 원본 이미지를 재사용하고, 하단 내비게이션은 선택 색상이 정확히 적용되는 투명 벡터 아이콘을 사용한다.
- 서비스 소개는 가로 스크롤 카드로 배치하고 전체보기는 현재 제공 기능을 설명하는 안내 창으로 연결한다.
- Android 시스템 상태 표시줄, display cutout과 내비게이션 영역을 고정 바와 스크롤 콘텐츠에 반영한다.

## 남은 범위

- 알림 아이콘은 별도 알림함 계약이 없어 현재 문의 화면 진입점으로 사용한다.
- 위치와 주변 매니저 수는 검증된 서버 필드가 추가되기 전까지 노출하지 않는다.
- Figma 두 번째 소개 카드의 AI 표현은 실제 기능 계약이 확정되면 문구와 진입 동작을 다시 검토한다.

## 검증

- `.\gradlew.bat assembleDebug --console=plain --max-workers=1` 성공
- `lintDebug`의 기존 오류 7건과 이번 화면의 경고를 분리해 확인
- Galaxy S22 실기기에서 상태 카드, 2×2 빠른 메뉴, 진행 로드맵, 서비스 소개와 고정 하단 내비게이션의 전체 스크롤 렌더링을 확인
- 환자·보호자 역할 모두에서 문구와 상태 표시를 확인하고, 진행 현황, 동행 신청, 건강정보, 일정·이력, 문의와 하단 내비게이션의 실제 화면 이동을 확인
- 실제 Core API의 일시적 서버 오류 상태와 서버에 의존하지 않는 Mock 데이터 상태를 각각 확인하고, 검증에만 사용한 Mock 빌드 설정은 소스에서 제거

# Figma 환자 예약 신청 완료 화면 구현

기준일: 2026-09-12

## 기준

- Figma 파일: `보들 MVP` (`NX07k3Tu4cLc6YgAV82RXp`)
- 대상 노드: `예약 신청완료(환자)` (`8:2751`)
- Android 진입점: `BookingCompletionActivity`

## 설계 판단

- 작업 목적: 예약 저장 성공 뒤의 임시 요약 화면을 Figma의 성공 안내, 진행 단계, 예약 상세, 하단 동작 구조와 일치시킨다.
- 선택한 방식: 기존 저장 성공 시점과 `BookingCompletionSnapshot` 계약은 유지하고, 완료 화면 전용 모델과 바인더가 Figma에 필요한 정보만 렌더링하도록 정리한다.
- 대안: 예약 신청 폼 전체와 완료 화면을 한 PR에서 함께 바꾸거나 Figma 화면을 정적인 예시 데이터로만 구현하는 방식을 검토했다.
- 선택 이유: 현재 MVP에서는 실제 저장 응답을 유지하는 것이 가장 중요하며, 완료 화면만 독립적으로 바꾸면 열린 예약 일정 선택 PR과의 충돌도 줄일 수 있다.
- 리스크: Figma 시안의 하단 버튼은 대비가 거의 없는 상태로 표현되어 있어 그대로 구현하면 조작이 어렵다. 기존 디자인 토큰의 파란색 기본 버튼을 사용해 기능성과 접근성을 보완했다.

## 구현 범위

- 성공 아이콘, 3단계 진행 표시, 예약 상세 카드, 하단 고정 안내 영역을 Figma 간격과 색상 토큰에 맞췄다.
- 병원과 진료과, 날짜와 시간을 분리해 표시하고 API의 `yyyy-MM-dd HH:mm` 값은 한국어 날짜·오전/오후 형식으로 변환한다.
- 신규 신청과 예약 수정이 같은 화면을 공유하되 상단 제목과 안내 문구는 실제 처리 결과에 맞게 구분한다.
- `예약 내역 보기`는 기존 `ClientBookingHistoryActivity`로 연결한다.
- Figma에서 내려받은 SVG 경로를 Android VectorDrawable로 옮겨 아이콘 모양을 유지한다.

## 남은 범위

- 매니저 배정 진행률은 이 화면이 실제 저장 직후에만 열리는 현재 계약에 맞춰 `매니저 찾는 중`으로 고정한다.
- 서버가 완료 화면 상태를 별도로 내려주는 계약이 생기면 진행 표시를 상태 모델 기반으로 전환한다.

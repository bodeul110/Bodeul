# Figma MVP 매니저 홈 구현 판단

- 작업 목적: Figma MVP의 매니저 홈 대기 화면(`8:2479`)을 기존 Android 기능 흐름과 겹치도록 구현한다.
- 선택한 방식: 기존 `ManagerActivity`와 화면 모델의 View ID·클릭 동작은 유지하고, XML 레이아웃·카드 바인더·Figma 원본 에셋 중심으로 화면 구조를 교체한다.
- 검토한 대안: Figma 문구와 숫자를 정적으로 복제하거나, 매니저 홈 로직 전체를 새 화면으로 다시 만드는 방식을 검토했다.
- 선택 이유: 현재 MVP에서는 배정 상태와 서류 상태가 실제 저장소 값에 따라 달라지므로, 존재하지 않는 위치·주변 매니저 수를 표시하지 않으면서 기존 기능 회귀와 열린 PR 충돌을 줄이는 편이 안전하다.
- 리스크: Figma의 위치 문구, 주변 매니저 수, 알림 화면은 현재 데이터 계약이나 이동 기능이 없어 시각 요소만 반영되며, API가 추가되면 화면 모델을 확장해야 한다.

## 이번 적용 범위

- 상단 앱 바, 인사 영역, 매칭 상태 카드, 2×2 빠른 메뉴, 서비스 소개 카드, 하단 내비게이션 순서와 스타일
- Pretendard 글꼴과 Figma MVP 색상 토큰
- Figma에서 직접 내보낸 서비스 소개 이미지와 화면 아이콘
- 서류 등록, 일정 등록, 동행 이력, 문의, 가이드, 프로필 이동 동작 유지

## 후속 연결 조건

- 위치 배지는 매니저 활동 지역 데이터가 API에 추가되면 실제 값으로 교체한다.
- 매칭 인원과 수락 목록은 예약 공개·수락 API가 확정되기 전까지 가짜 숫자를 노출하지 않는다.
- 알림 아이콘은 알림 목록 또는 딥링크 계약이 추가될 때 클릭 동작을 연결한다.
- 진행 중 동행 홈은 관련 가이드 상태 PR이 병합된 뒤 Figma 노드 `8:1624`를 기준으로 별도 반영한다.

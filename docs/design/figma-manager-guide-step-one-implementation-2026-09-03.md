# Figma MVP 동행 가이드 1 구현 판단

- 작업 목적: Figma MVP `동행 가이드 1`(`8:3242`)을 현재 Android의 `MEETING_CONFIRMATION` 단계와 같은 화면 흐름으로 구현한다.
- 선택한 방식: `ManagerGuideActivity`와 기존 단계 진행 API를 유지하고, 상봉 단계일 때만 전용 상단 안내·동행 정보·지도·고정 CTA를 렌더링한다. 다른 단계는 기존 동적 화면을 유지한다.
- 검토한 대안: 13개 Figma 프레임마다 Activity를 만들거나 Figma 예시 데이터를 정적으로 표시하는 방식은 서버의 가변 단계 계약과 실제 예약 정보를 중복시키므로 제외했다.
- 선택 이유: 현재 MVP 규모에서는 한 Activity가 `currentStepCode`를 기준으로 상태를 전환해야 진행 판정과 입력 저장 로직을 우회하지 않으면서 화면을 단계별로 보정할 수 있다.
- 리스크: 현재 예약 계약에는 환자 나이와 성별이 없어 Figma 예시의 `72세, 여성`은 표시하지 않는다. 해당 필드가 서버 계약에 추가되면 동행 정보 모델을 확장해야 한다.

## 반영 범위

- Figma의 `Step 01. 매칭 및 상봉` 상단 앱 바와 상봉 안내 위계를 적용했다.
- 환자명, 상봉 장소, 진료 과목은 `ManagerDashboard`의 실제 예약 데이터를 사용한다.
- `MEETING_CONFIRMATION`에서도 지도 카드를 표시하고 지도 액션은 `상봉 위치 확인하기` 하나로 제한한다.
- 상봉 완료 CTA는 기존 `ManagerGuideProgressPolicy`와 서버 진행 요청을 그대로 사용한다.
- 상봉 전용 요약 카드에서도 기존 안심 채팅을 열 수 있도록 같은 채팅 흐름에 연결된 진입점을 유지한다.
- 가이드 화면 하단에 홈·일정/이력·동행방·내 정보 내비게이션을 연결하고 현재 동행방을 활성 상태로 표시한다.
- 손잡기, 정보, 위치, 진료과, 뒤로가기, 화살표 아이콘은 Figma 원본 내보내기 파일을 Android 리소스로 저장했다.
- 디버그 전용 임시 상태로 실기기에서 상단 안내, 동행 정보, 지도 액션, 완료 CTA의 배치와 아이콘 렌더링을 확인한 뒤 임시 코드는 제거했다.
- 160dp 지도 높이와 48dp 지도 카드 반경은 상봉 단계에만 적용하며, 다른 단계의 기존 250dp/28dp 지도 표현은 유지한다.

## 남은 범위

- 실제 서버의 `MEETING_CONFIRMATION` 세션으로 지도 데이터와 진행 요청까지 종단 검증한다. 현재 연결 계정은 `GUIDE_NOT_READY`라 실제 상태 전환은 확인하지 못했다.
- 동행 가이드 2 이후는 각 `stepCode`와 Figma node를 한 단계씩 대조해 별도 묶음으로 보정한다.
- 환자 나이·성별은 서버 데이터 계약 전까지 화면에 추정해서 표시하지 않는다.

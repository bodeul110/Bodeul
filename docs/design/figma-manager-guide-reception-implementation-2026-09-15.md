# Figma MVP 동행 가이드 접수 단계 구현 판단

- 작업 목적: Figma MVP `동행 가이드 3`(`8:835`)의 접수·대기 화면을 Android `RECEPTION_QUEUE` 단계에 맞춰 분리한다.
- 선택한 방식: 기존 `ManagerGuideActivity`의 단계 진행 정책을 유지하고 접수 단계에서만 전용 화면을 바인딩한다. 대기번호와 예상 대기 시간은 매니저가 직접 입력해 기존 `guardianUpdate` 필드에 저장한다. 알림이나 채팅 전송을 가정하지 않는다.
- 검토한 대안: Figma 예시값 `128`, `35분`, 환자 확인 배지를 고정 표시하거나 별도 대기정보 API를 가정하는 방식은 실제 세션 데이터 및 서버 계약과 다르므로 제외했다. 바코드 스캔 버튼도 현재 스캔 기능이 없어 표시하지 않는다.
- 선택 이유: `RECEPTION_QUEUE`에 구조화된 대기번호·대기시간 필드는 없지만 기존 보호자 공유 메모 필드에는 저장할 수 있다. 피그마의 ‘전달하기’ 표현과 달리 현재 서버가 보장하는 것은 저장뿐이므로 화면은 ‘저장하기’로 안내한다.
- 리스크: `guardianUpdate`는 단일 필드이므로 새 대기 정보를 저장하면 이전 공유 문구가 교체된다. 보호자 계정 연결과 `CHAT` 공유 권한이 없으면 보호자 화면에 표시되지 않을 수 있고 별도 전송 이벤트도 없다. 앱 재실행 뒤 입력칸은 빈 상태이며 저장된 내용은 읽기 전용으로 다시 보인다. 다른 동행 세션으로 바뀌면 이전 환자의 임시 입력을 지운다. 서버에 전용 필드가 생기면 입력 모델과 전달 계약을 함께 이관해야 한다.

## 화면과 동작

- 상단 제목은 서버 `GuideStep` 순서·제목에서 만든 기존 툴바 문자열을 사용한다. Figma 정적 단계번호는 고정하지 않는다.
- 접수 단계의 제목, 두 개의 입력 카드, 환자 정보, 보호자 공유 CTA는 Figma의 색상·간격·카드 위계를 적용한다. 원본 프레임과 SVG는 `assets/manager-guide-reception`에 보관하고 큐·시계·환자·알림 아이콘은 Android 벡터로 변환했다.
- 환자명·병원명·진료과는 실제 `ManagerDashboard`에서 읽는다. 값이 비어 있으면 확인 중 안내를 표시한다.
- 대기번호는 20자 이내, 예상 대기는 1~999분을 검증한다. 유효한 입력일 때만 기존 `saveGuardianUpdate`를 호출한다.
- 기존 현장 메모 카드는 접기/펴기 버튼 뒤에 남기고 고정 `접수 완료` CTA도 유지한다. 보호자 공유 내용을 저장하는 것과 서버 단계를 완료하는 것은 별개의 동작이다.
- 다른 단계의 기존 화면 바인딩·입력 저장·지도/리포트 로직은 변경하지 않는다.

## 검증과 후속 조건

- `assembleDebug`와 `testDebugUnitTest`가 통과했다.
- 실기기 `SM_S901N`에서 임시 디버그 미리보기를 사용해 실제 레이아웃과 아이콘 렌더링, 입력 필드의 키보드 표시를 확인했다. 첫 캡처에서 상단 제목 중앙 정렬과 시간 단위 간격이 피그마와 달라, 접수 전용 전체 폭 앱 바 및 입력 간격으로 보정했다. 미리보기 코드는 검증 후 제거했다.
- 실제 매니저 로그인 후 홈·가이드 데이터 조회를 시도했지만 동행 세션 API가 HTTP 500/503을 반환해 홈 대시보드 자체가 로드되지 않았다. 따라서 이 검증은 **샘플 데이터로 레이아웃을 렌더링한 시각 검증**이며, 실제 `RECEPTION_QUEUE` 세션의 보호자 메시지 저장/교체와 접수 완료 진행은 확인되지 않았다.
- 서버 응답이 복구되고 실기기 계정이 `RECEPTION_QUEUE` 단계에 도달하면 입력 오류, 보호자 메시지 저장/교체, 접수 완료 버튼의 서버 진행 판정을 종단 검증한다.
- 전용 대기정보 API 또는 바코드 스캔 기능을 요구하려면 백엔드 계약 및 기능 범위를 별도 이슈로 합의한다.
- 2026-09-15 리뷰 전 보완에서 세션 변경 시 임시 대기 입력을 초기화하고, 알림 전송이 아닌 저장 동작에 맞춰 문구를 고쳤다. 새 세션 초기화 정책 JUnit 3건은 컴파일된 테스트를 직접 실행해 통과했고 `assembleDebug`도 성공했다.
- 보완 후 `lintDebug`는 기존 오류 7건 때문에 실패했지만 새 툴바 tint 오류는 제거했다. 실기기가 연결되지 않아 이번 세션 전환과 실제 보호자 화면 반영은 종단 검증하지 못했다.

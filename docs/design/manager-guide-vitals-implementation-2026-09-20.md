# 매니저 기초 측정 화면 구현 기록

## 목적

Figma MVP의 `동행가이드4`(`8:899`)를 현재 Android `VITALS_CHECK` 단계에 연결한다. 화면에는 혈압, 심박수, 체중을 선택 입력으로 제공하고, 예시 수치는 힌트로만 표시해 실제 측정값으로 오인되지 않게 한다.

## Figma 대응

- 상단 단계·제목·진행 막대와 환자명 안내 문구를 전용 화면 위계로 구성한다.
- 혈압은 수축기와 이완기를 한 쌍으로 입력한다.
- 심박수와 체중은 단위를 입력란 밖에 고정해서 값과 단위를 구분한다.
- 심장, 심박수, 체중 아이콘은 Figma node가 제공한 SVG path를 Android vector로 변환해 사용한다.
- 기본 동행 가이드의 공통 요약·미리보기·현장 메모 카드는 이 단계에서 숨기고, 하단 진행 CTA와 내비게이션은 기존 흐름을 재사용한다.

## 데이터 연결

현재 Core API에는 혈압·심박수·체중의 독립 필드가 없다. 프론트엔드가 임의의 서버 필드를 만들지 않고 기존 `fieldPhotoNote`에 다음 형식으로 저장한다.

```text
[기초 측정]
혈압: 120/80 mmHg
심박수: 72 bpm
체중: 68.5 kg
```

모든 항목은 선택 입력이다. 혈압은 한쪽만 입력할 수 없고, 입력된 값은 양수 형식인지 확인한다. 이전 버전에서 작성한 비정형 현장 메모가 있고 새 측정값을 입력하지 않은 경우에는 기존 메모를 그대로 보존한다.

CTA는 `fieldPhotoNote` 저장 성공 뒤 같은 세션과 `VITALS_CHECK` 단계가 유지되는지 다시 확인한 다음 단계 이동을 요청한다. 저장 실패 시 이동하지 않으며, 저장은 성공했지만 이동이 실패하면 저장된 대시보드를 다시 표시해 재시도할 수 있게 한다.

## 리뷰 후 저장 경계 보완

- 작업 목적: 세션이 바뀐 뒤 이전 환자의 측정값이 새 세션에 쓰이거나, 앱 복귀 시 미저장 입력이 사라지는 일을 막는다.
- 선택한 방식: 기초 측정 전용 저장 호출에 기대 세션 ID와 단계 코드를 전달한다. 저장소가 현재 활성 세션을 다시 확인하고, Core API의 버전 조건으로 확인 후 동시 단계 변경도 거부한다. 네 필드의 입력 중 원문은 세션 ID와 함께 `SavedStateHandle`에 보관해 같은 세션의 재조회·화면 재생성에서만 복원한다.
- 대안: 저장 후 세션 비교만 유지하거나 로딩 때 화면 참조만 보존하면 각각 오기록과 화면 재생성 시 소실을 막지 못한다.
- 선택 이유: 현재 MVP의 기존 서버 PATCH 계약과 일반 현장 메모 저장을 유지하면서 기초 측정 경로만 좁게 보호할 수 있다.
- 리스크: 저장 전에 다른 기기에서 단계를 변경하면 재입력이 필요하다. 입력 초안은 세션이나 단계가 실제로 바뀌거나 저장이 성공할 때 제거한다.

## 현재 제약

- `fieldPhotoNote`는 여러 가이드 단계가 공유하는 최신 메모 필드라 다음 단계의 저장으로 교체될 수 있다.
- 측정 시각과 측정 주체는 별도 계약이 없어 저장하지 않는다.
- 의료적 정상 범위를 앱이 판정하거나 경고하지 않는다. 현재 검증은 입력 형식과 양수 여부에 한정한다.
- 단계별 측정 이력, 구조화 조회와 의료적 검증이 필요하면 백엔드 DTO·보관·권한 계약을 먼저 추가해야 한다.

## 검증

- `ManagerGuideVitalsDraftTest`: 단위 포함 직렬화·역직렬화, 비정형 메모 구분, 선택값과 숫자 형식 검증
- `testDebugUnitTest`: 전체 단위 테스트 통과
- `assembleDebug`: Debug APK 빌드 통과
- `lintDebug`: 기존 API 26 관련 6건과 기존 include layout 1건 때문에 실패했으며 이번 변경 파일에는 오류가 없다.
- 실제 기기에서 `VITALS_CHECK` 세션의 키보드, 저장 성공, 다음 단계 이동은 개발 Core API 주소와 테스트 세션이 준비된 뒤 확인한다.

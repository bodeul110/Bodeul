# Issue 395 만남 위치 선택 화면 실기기 수정 기록

기준일: 2026-09-02

## 작업 목적

edge-to-edge 실기기에서 만남 위치 확인 버튼이 시스템 탐색 영역에 가리고 추천 위치 목록이 0px로 접혀 예약을 완료할 수 없는 문제를 해결한다.

## 선택한 방식

- 지도와 설명을 선택 불가능한 `ListView` 헤더로 옮겨 추천 위치 카드와 함께 한 방향으로 스크롤한다.
- 확인 버튼은 목록과 분리한 고정 하단 동작으로 두고 navigation bar와 display cutout inset을 기존 padding에 더한다.
- 추천 위치 카드는 목록 헤더 개수를 보정한 표준 `ListView` 선택 이벤트로 지도 탭과 같은 선택 경로를 사용한다.

## 대안

- 하단 padding이나 `fitsSystemWindows`만 추가할 수 있다.
- 고정된 지도 높이를 줄여 목록 공간을 만들 수 있다.
- 전체 화면을 `ScrollView`로 감싸고 기존 `ListView`를 중첩할 수 있다.

## 선택 이유

현재 화면은 지도 높이와 여러 줄 제목 때문에 목록 높이가 이미 0px였다. 하단 inset이나 지도 높이만 조정하면 화면 크기와 글자 크기에 따라 다시 깨질 수 있다. 기존 `ListView`를 주 스크롤 컨테이너로 유지하면 중첩 스크롤 없이 지도와 네 후보 카드에 모두 접근할 수 있고, 고정 하단 동작은 프로젝트의 기존 화면 패턴과도 맞는다.

## 구현한 내용

- 위치 선택 화면을 스크롤 목록과 고정 하단 확인 영역으로 분리했다.
- 기존 헤더, 안내와 지도 UI를 별도 목록 헤더 레이아웃으로 이동했다.
- 상태 표시줄, display cutout과 시스템 탐색 영역 inset을 상하좌우에 반영했다.
- 후보 카드 선택이 터치와 키보드·보조 입력에서도 선택 badge, 지도 선택 상태와 예약 폼 결과에 반영되도록 표준 목록 선택 경로를 유지했다.
- 선택 가능한 카드가 목록의 터치 이벤트를 가로채지 않도록 카드 자체의 긴 누르기를 비활성화했다.
- 회전 등으로 화면이 재생성될 때 현재 선택 ID를 저장하고 유효한 후보로 복원하도록 했다.

## 리스크와 남은 범위

- 기본·1.3배 글자 크기와 세로·가로, 3버튼·제스처 탐색을 확인했지만 더 큰 접근성 글자 크기와 다른 화면 비율은 확인하지 않았다.
- 실기기 검증은 `SM-S921N` Android 16 한 기종에서 수행했으며, 화면 회전과 시스템 영역 회귀를 자동화한 계측 테스트는 아직 없다.
- 목록 헤더 안의 지도는 세로 스크롤과 탭을 함께 처리하므로 향후 지도 드래그 동작을 추가할 때 터치 충돌을 다시 확인해야 한다.

# Notion 정책 충돌 해소 결과

기준일: 2026-08-30

> 2026-09-01 후속 기획 결정으로 위치, 결제와 가이드 2 결론이 일부 대체됐다. 현재 기준은 [Notion 제품 기준 정합성](../planning/notion-product-alignment.md)을 따른다. 환자 GPS 1분 공유는 동의·철회·인가·파기 종단 검증 전 production `OFF`, 실제 무통장입금은 운영 준비 전 수취 `OFF`, 가이드 2 영상은 승인 자산·권리·비식별 검수 전 노출 `OFF`다. 아래 내용은 2026-08-30 당시 판단 기록으로 보존한다.

## 작업 목적

Notion의 개발 정책, MVP 통합본, 상세 명세, 채팅 명세와 보유기간 문서가 서로 다른 아키텍처·위치·보관·서류·채팅 기준을 담고 있어 현재 구현과 법률상 최소수집 원칙을 함께 대조해 단일 기준을 정했다.

## 판단 원칙

- 코드나 설정으로 되돌릴 수 있는 제품값은 이미 검증된 구현을 유지한다.
- 민감정보 수집, 위치, 권한 확대와 비가역 삭제는 최소수집·비활성·fail-closed를 우선한다.
- 법정 거래·분쟁 기록은 일반 채팅, 첨부, 위치와 서류 원본에서 분리한다.
- 정책값 확정과 production 활성화·삭제 apply 승인은 별도 단계로 관리한다.

## 구현과 남은 차이

확인 기준은 `master` 커밋 `6df7b28d7a0b73d070109ecc8d0d86956893d843`과 PR #380 커밋 `31aca1fd12b77256090c7560ee61c9ff88d53c06`이다.

1. 위치 코드는 1회·연속 공유가 노출되지만 production 강제 OFF가 없다. `CARE_ENDED` 이후 write 거부는 구현됐으며, 남은 범위는 앱 UI와 Core API에 `off` 모드를 강제하는 작업이다.
2. PostgreSQL V18에는 `CARE_ENDED`부터 신규 채팅·첨부·위치 차단, TTL 시작, 배정 매니저의 채팅·첨부·건강정보·위치 조회 회수가 반영됐다. Firestore 전환 파기 함수는 아직 `COMPLETED/CANCELED`만 종료로 판단하므로 `CARE_ENDED` 시작점과 fixture 재검증이 남았다.
3. PR #383의 파일 형식·용량 강화는 맞지만 신분증·범죄경력을 필수로 요구한다. 자격 증빙 1종으로 줄이고 `healthCertificate` legacy 이름을 `nursingLicense`로 이관해야 한다.
4. PR #380의 공고번호 계약은 기준과 맞지만, 병합된 V18 위에서 충돌을 해소하고 migration·Core API·Android 검증을 다시 통과해야 한다.
5. production 자동 파기는 정책값이 정해졌어도 처리방침, 책임자, 복원·삭제 재적용 검증 전까지 비활성으로 둔다.
6. 결제 영수증·처방 이미지 같은 동행 증빙은 30일 보관 목표와 달리 만료 필드·자동 파기 연계가 없다. 구현과 dry-run 검증 전 production 업로드를 활성화하지 않는다.
7. 구조화 건강정보와 최종 리포트는 1년 정책 상한이 있지만 현재 만료 필드와 자동 파기 계약이 없다. production apply 전 처리방침·법률 대조와 구현·복원 후 재삭제 검증이 필요하다.

## 목적과 판단

## 갱신 내용

- 현재 Figma 파일, 최근 화면 병합과 내부 테스트 후속 항목을 구현 상태·화면 지도에 반영했다.
- Core API·Firebase 잔존 기능·Mock 경계, 환자 전용 예약 쓰기, 관리자 PostgreSQL 세부 역할·제한 함수 실행을 대조했다.
- Firestore Core 업무 직접 쓰기 금지, 관리자 브라우저 직접 접근 차단, 자격 증빙 1종·10 MiB·서버 원문 조회를 Rules 문서에 반영했다.
- [Migration 목록](../architecture/database-migration-catalog.md)을 추가해 소스 V23과 환경별 적용 증적을 구분했다.
- legacy 매니저 GPS 기본 OFF와 기기 내 현재 위치 보기, 환자 GPS 제품 목표를 분리했다.
- 관리자 웹의 환경 표시·Auth 등록과 운영 DB·역할·MFA·실제 업무 검증을 분리했다.
- 운영 전환일·유료 전환일의 임시 날짜를 확정 일정에서 제외하고 게이트 기반 절차로 바꿨다.
- Codex/CLI 개발, 별도 관리자 웹 실행 경로, Firebase 점검 범위와 dry-run 우선 절차를 정리했다.
- 현재 문서 색인과 깨진 링크를 수정하고 과거 보안·데이터 문서에는 역사적 범위를 표시했다.
- 웹 저장소의 작업 규칙·PR 양식에서 종료된 Hosting·Node API 전제를 정리했다. 현재 test/lint/Next.js/Vite 검증을 기준으로 안내한다.

## 검증

- 최초 대상은 메인 195개와 웹 7개, 총 202개 Markdown 문서였다. 새 migration 목록과 이 기록을 포함한 최종 대상은 204개다.
- 두 저장소 전체 Markdown에 대해 엄격한 UTF-8 해석과 대체 문자를 검사했다. 상대 링크와 두 저장소 `master` 참조의 파일·디렉터리·제목 앵커 978건은 오류 0건이었다.
- 링크 검사는 로컬에서 참조 대상을 대조하는 방식이다. 모든 외부 URL의 로그인·응답 상태나 모든 문장을 자동 검증하는 검사는 아니다.
- 두 저장소 `git diff --check`가 통과했다.
- 변경은 Markdown에 한정한다. 앱·Core·Functions·Rules·DB를 바꾸지 않았으므로 로컬 빌드·실기기·에뮬레이터를 재실행하지 않는다. PR CI 결과는 해당 PR에서 별도로 확인한다.

## 남은 범위

- #429 Preview API 500/503은 재확인 필요 항목이다. 이번 작업으로 현재 장애나 복구를 단정하지 않는다.
- 운영 Supabase는 [9월 21일 환경 기록](admin-web-environment-display-2026-09-21.md)의 일시정지 상태와 계정 등록 경계를 유지한다. DB 재개·migration·역할 부여·결제·파기는 실행하지 않았다.
- 최근 병합 화면의 실기기 재시험, 보호자 예약·내부 STT·영상 플레이어와 운영 App Check 등은 [구현 상태](../status/implementation-status.md)에 남긴다. 문서 수정만으로 이슈를 닫지 않는다.
- 원 작업 폴더의 기존 사용자 변경·로컬 환경 파일·미추적 계획서는 별도 작업 상태로 보존하고 이 변경에 포함하지 않았다.

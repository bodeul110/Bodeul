# 성인 환자·보호자 정보공유 동의 계약

기준일: 2026-08-28

상태: Core API 순수 판정 계약만 구현, DB·API·Android·production 권한 미연결

## 작업 목적

성인 환자가 지정 보호자에게 정보 종류별 권한을 직접 부여하고 철회하는 확정 원칙을 서버가 일관되게 판정할 수 있는 최소 계약으로 만든다.

## 선택한 방식

`AdultPatientGuardianSharingPolicy`가 환자 본인 행위, 지정 보호자, 정보 범위, 동의 정책 버전, 시작·만료·철회 시각을 모두 확인한다. 판정 호출자는 현재 적용 중인 정책 버전을 명시적으로 전달해야 하며, 저장된 동의 버전과 다르면 기본 거부한다. 예약, 위치, 채팅, 첨부, 리포트를 서로 다른 범위로 취급하고 하나라도 맞지 않으면 기본 거부한다.

| 정보 범위 | 코드 | 실제 API 연결 상태 |
| --- | --- | --- |
| 예약 | `APPOINTMENT` | 미연결 |
| 위치 | `LOCATION` | 미연결 |
| 채팅 | `CHAT` | 미연결 |
| 첨부 | `ATTACHMENT` | 미연결 |
| 리포트 | `REPORT` | 미연결 |

동의 기간의 기본값은 정하지 않는다. 호출자가 시작 시각과 만료 시각을 명시해야 하며, 만료 시각은 시작 시각보다 늦어야 한다. 철회 시각부터는 즉시 거부한다.

## 대안

- 예약 참여 관계만으로 보호자의 모든 정보 열람을 계속 허용한다.
- 정보 범위 하나로 모든 예약·진료·위치·채팅 데이터를 묶는다.
- 정책에 기본 동의 기간을 넣고 DB·API·화면까지 한 번에 연결한다.

## 선택 이유

현재 승인된 내용은 성인 환자의 자기결정과 정보 종류별 부여·철회 원칙이다. 반면 동의 기간 기본값, 증적 형식, 기존 예약 참여자의 전환 방식과 대리권은 확정되지 않았다. 따라서 승인된 불변식만 순수 계약으로 고정하고 실제 접근권한은 바꾸지 않는다.

## 판정 규칙

- 행위자의 역할이 `PATIENT`이고 행위자 ID와 환자 ID가 같아야 동의를 만들거나 철회할 수 있다.
- 대상 계정은 `GUARDIAN` 역할이어야 하며 환자 본인과 달라야 한다.
- 하나 이상의 정보 범위, 동의 당시 정책 버전, 시작·만료 시각이 필수다.
- 판정 시점의 현재 정책 버전도 필수이며 저장된 동의 버전과 일치하지 않으면 `POLICY_VERSION_MISMATCH`로 거부한다.
- 동의가 없거나 환자·보호자·범위가 다르면 거부한다.
- 시작 전, 만료 시각부터, 철회 시각부터 거부한다.
- 같은 철회 요청은 첫 철회 시각과 버전을 유지한다.

## 현재 영향

- PostgreSQL migration과 실제 동의 데이터 쓰기는 추가하지 않았다.
- Core API endpoint와 기존 예약·세션·채팅·첨부·리포트 인가에는 연결하지 않았다.
- Android 동의 화면과 보호자 조회 화면을 바꾸지 않았다.
- 기존 production 접근권한은 확대하거나 축소하지 않았다.

## 후속 연결 조건

1. 성인 여부 확인 근거와 기존 참여자의 동의 전환 방식을 정한다.
2. 동의 기간 선택지, 정책 버전 원본과 현재 버전의 공급 경계, 사용자에게 제시할 문구와 감사 증적 형식을 확정한다.
3. PostgreSQL 현재 상태와 변경 이력을 분리해 저장하고 Core runtime만 쓰도록 제한한다.
4. 환자 전용 부여·철회 API와 Android 화면을 함께 구현한다.
5. 예약·위치·채팅·첨부·리포트 API를 각각 해당 범위 판정에 연결하고 미동의·철회 회귀 테스트를 통과한다.
6. 의사결정능력이 제한된 환자의 대리권 흐름은 법률 회신과 관리자 승인 설계 뒤 별도로 구현한다.

## 리스크

- 이 계약만으로 실제 보호자 열람이 제한되지는 않는다. API 인가 연결 전에는 구현 완료로 표시하면 안 된다.
- 정보 범위와 기존 응답 필드의 매핑이 잘못되면 일부 민감정보가 넓게 노출되거나 정상 조회가 막힐 수 있다.
- 정책 버전과 증적을 저장하지 않으면 사후에 어떤 문구에 동의했는지 입증할 수 없다.
- 현재 정책 버전을 잘못 공급하면 유효한 동의도 거부될 수 있으므로 실제 API 연결 전에 단일 공급 경계와 배포 절차를 정해야 한다.

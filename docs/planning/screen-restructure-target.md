## 목표 정보 구조

### 1. 진입·인증

1. 첫 화면
2. 권한 안내
3. 로그인·회원가입
4. 사용자 유형 선택
5. 매니저 자격 인증
6. 매니저 승인 대기·보완 요청

권한은 Figma의 일괄 필수 표기를 그대로 따르지 않고 실제 기능 진입 시 최소 범위로 요청한다. 로그인 제공자는 실제 활성화·검증 상태를 기준으로 노출한다.

### 2. 환자·보호자 예약

1. 환자·보호자 홈
2. 병원·진료과 검색
3. 방문 날짜·시간
4. 환자 건강·이동 정보
5. 요청사항과 결제 요약
6. 예약 신청 완료와 매칭 대기

보호자가 환자를 대신 예약하는 흐름은 유지하되, 진료정보 공유 범위와 철회는 별도 기획·법률 결정이 필요하다.

### 3. 매니저 매칭

1. 매니저 홈
2. 수행 가능한 요청 목록
3. 요청 상세와 최소 공개 정보
4. 한 명의 매니저 수락이라는 제품 목표
5. 매칭 완료와 확정 일정

현재 PostgreSQL 배정 함수는 관리자 runtime만 실행할 수 있고 매니저 self-accept API는 없다. self-accept를 구현할지는 별도 제품 결정이며, Figma의 `선착순` 문구만으로 개인정보 공개 범위나 DB 권한을 바꾸지 않는다.

### 4. 동행 수행

Figma는 아래 13개 화면을 제시한다.

1. 매칭·상봉
2. 병원 이동
3. 접수·대기
4. 기초 측정 기록
5. 문진 준비
6. 진료 보조·기록
7. 진료 리포트 확인
8. 수납·결제 증빙
9. 약국 이동
10. 처방 관련 자료 등록
11. 복약 확인
12. 환자 최종 확인·동행 종료
13. 매니저 일지·후기 진입

현재 서버는 병원 가이드 데이터의 단계 수를 사용한다. Figma 13개 화면은 화면 목표이며 `currentStepOrder=1..13` 고정 계약이 아니다. 녹음·STT·AI 요약과 OCR은 화면에 보여도 후속 기능으로 유지한다.

### 5. 진행 공유·채팅

1. 제품 목표인 동행 단계 기반 시스템 진행 이벤트
2. 현재 구현된 환자·보호자·매니저의 짧은 직접 메시지
3. 읽음 상태와 FCM 보조 알림
4. 이미지·PDF 첨부
5. 현재 위치와 최근 위치 이력
6. 재연결 시 API snapshot 복구

Figma의 채팅형 화면 6개는 시각 시안이며 prototype 연결은 없다. 현재 DB는 참여자가 직접 보낸 메시지만 저장하고 가이드 시스템 이벤트를 채팅 메시지로 생성하지 않는다. 실제 참여자·권한·보관 계약은 Core API와 운영 문서를 따른다.

### 6. 종료·후속 처리

1. 최종 동행 리포트
2. 만족도·후기
3. 정산·결제 후속 문의
4. 고객지원·긴급 신고
5. 매니저 이력·정산 화면

실제 PG 승인, 환불, 노쇼, 초과 시간 추가 결제와 매니저 출금은 화면과 저장 상태만으로 운영 완료로 보지 않는다.

## 현재 구현 해석

| 화면 축 | 현재 상태 | 남은 핵심 |
| --- | --- | --- |
| 진입·역할·자격 인증 | 기본 사용자 흐름 구현 | Figma 문구와 실제 권한·로그인 제공자 정합성 |
| 예약·매칭 | Core API·PostgreSQL과 관리자 배정 경로 구현 | 매니저 self-accept 여부, 운영 가격·결제·취소·환불 정책 |
| 동행 가이드·리포트 | 데이터 기반 단계와 리포트 구현 | Figma 1~13 명칭·이벤트 정규화 |
| 채팅·위치 | 직접 채팅·위치의 Core API·Realtime·FCM 실기기 검증 | 시스템 이벤트 동행방 여부, 운영 모니터링과 production 전환 게이트 |
| 첨부 | Core API 중계 업로드·다운로드와 파기 리허설 | production 적용과 법률 문서 대조 |
| AI 음성·STT·OCR | 미구현 | 동의·외부 처리·보관 정책 확정 후 개발 |
| 결제·정산 | 상태와 화면 중심 | 실제 PG·환불·노쇼·초과요금·출금 계약 |

## 화면 정리 우선순위

1. 역할이 섞인 환자·매니저 홈 카드와 호칭 교정
2. 권한 안내를 Android 최소 권한 정책에 맞게 수정
3. 동행 가이드 1~13 frame 이름과 내부 단계 번호 정규화
4. 하단 내비게이션과 제품 용어 통일
5. Figma 샘플 사용자·날짜·성별 fixture 통일
6. AI·OCR를 실제 동작으로 오해하지 않는 비활성·후속 표현 확정

## 운영 원칙

- Figma 화면이 추가됐다는 이유만으로 기능 범위를 자동 확대하지 않는다.
- Notion의 `실제 구현` 표기는 저장소 코드와 검증 기록으로 다시 확인한다.
- 구현되지 않은 항목은 화면에서 제거하거나 `후속 기능`으로 명확히 표시한다.
- 정책 결정이 필요한 항목은 [Notion 제품 기준 정합성](notion-product-alignment.md)에 남긴다.

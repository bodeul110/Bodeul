# MVP 임시 정책값 결정 경계

기준일: 2026-08-28

## 결정

MVP 기능 구현에 필요한 값이 아직 제품 정책으로 확정되지 않았더라도, 되돌릴 수 있고 실제 사용자·금전·권한·법정 의무에 영향을 주지 않는 값은 개발팀이 `MVP 임시값`으로 정해 진행한다. 이 문서는 제품 정책의 source of truth를 바꾸는 문서가 아니라 개발 수행 경계다. 이미 답변되거나 확정된 정책은 그대로 유지하며, 문서 사이의 충돌을 임시값으로 덮지 않는다.

## 빠른 판정

1. 기존 기획 답변이나 법률·보안 기준이 있으면 그 기준을 유지한다.
2. 실제 개인정보 수집·보관·삭제, 권한 확대, 비용 발생 또는 법정 의무 변경이면 별도 승인을 받는다.
3. 설정 변경으로 되돌릴 수 있고 local/dev/preview의 합성 데이터에만 영향을 주면 개발팀이 임시값을 정할 수 있다.
4. 판단이 모호하면 기능을 비활성화하거나 dry-run·fail-closed 상태로 구현한다.

## 개발팀이 정할 수 있는 범위

| 범위 | 예시 | 기본 조건 |
| --- | --- | --- |
| 화면 동작 | timeout, loading 시간, 표시용 정렬·필터, 빈 상태 | 자격·매칭·안전 우선순위나 접근권한에 영향 없음 |
| API·작업 처리 | 재시도 횟수, backoff, polling 간격, batch·page 크기 | 환경설정으로 교체 가능 |
| 개발 데이터 | fixture, preview seed, 비교 자료 cleanup 기간 | 합성 데이터와 비운영 환경에 한정 |
| 내부 운영 보조 | 읽기 전용 점검 항목, 합성 비운영 로그 순환 기간, dry-run 기본값 | production 감사·보안 로그 정책에 적용하지 않음 |
| 기능 노출 | 개발 feature flag, preview 전용 제한값 | production 기본은 비활성 |

알림 시점이나 대기시간처럼 제품 경험과 맞닿은 값은 비운영 테스트 계정과 시뮬레이션에서만 임시 구현할 수 있다. 실제 사용자에게 보내는 FCM·인앱·문자·알림톡, 외부 비용 발생 또는 개인정보 포함은 별도 승인 경계로 올린다.

## 별도 승인이 필요한 범위

- 개인정보·민감정보·위치·채팅·첨부·매니저 증빙 원본의 production 수집, 열람, 보관과 파기
- 동의·철회·대리권, 관리자 원문 접근, 역할·권한 부여와 회수
- 실제 결제·환불·정산·노쇼·보험·책임과 외부 서비스 과금
- 실제 사용자 알림의 수신자·이벤트·본문과 발송 시점
- 사고·안전 대응시간, 업무 완료·중단 조건과 상태 전이
- 계정과 production 데이터 삭제, 법정 보존, legal hold, backup 삭제 재적용
- 인증·인가·App Check·비밀값·감사·최소권한 기준 완화
- 개인정보처리방침, 위치기반 약관과 사용자에게 약속하는 보관·처리 문구

이 범위는 코드 골격, 계산 로직과 개발용 fixture 검증까지 진행할 수 있다. 실제 사용자 데이터에 쓰는 apply 경로와 production 권한은 승인과 실검증 전까지 비활성으로 유지한다.

## 임시값 기록 형식

| 필드 | 기록 내용 |
| --- | --- |
| 이름 | 설정 또는 기능 이름 |
| MVP 임시값 | 값과 단위 |
| 적용 환경 | local, dev, preview 중 실제 범위 |
| 선택 이유 | 현재 구현·검증에 필요한 이유 |
| 변경 위치 | 환경변수, 설정 파일 또는 feature flag |
| production 상태 | 비활성, dry-run, apply 금지 중 하나 |
| 재검토 조건 | 기획 답변, 법률 검토, 보안 검증 또는 출시 게이트 |

예를 들어 `개발 fixture cleanup 7일`은 임시값으로 사용할 수 있다. 이를 `사용자 채팅 보관 7일`로 확대해서는 안 된다. 현재 채팅 7일·180일, 첨부 7일·30일, 매니저 심사 원본 1년·30일 충돌은 production 승인 전까지 [데이터 보관 및 파기 정책](../operations/data-retention-policy.md)의 기술 안전망과 비활성 경계를 유지한다.
